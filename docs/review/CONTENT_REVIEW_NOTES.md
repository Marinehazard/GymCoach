# Content-author review notes on R4 numbers and flags (Phase 0, 2026-09-05)
Raised by the six exercise-content authors (WP-09..WP-14) while writing batch_1..6.json. Authors never change numbers; WP-02 (knowledge assets) and the integrator decide. Each note names the exercise id and the suspected inconsistency in docs/research/R4-exercise-taxonomy.md.

## batch_2.json (25 entries)
- CONTRADICTION (task brief vs SPEC): the brief asked for a top-level "review_notes": {id: text} map. SPEC §2 ContentOverlay has only schema_version/batch/entries/status and assets are decoded with CoreJson.assets (ignoreUnknownKeys = false, HR-9, §3), so a top-level review_notes key would make KnowledgeLoader fail on this file. SPEC ExerciseContent and R4 §6.2 both define review_notes as a per-entry STRING. Resolved per SPEC: objections are written as entries.<id>.review_notes strings on barbell_shrug, side_lying_dumbbell_external_rotation and prone_y_raise; no top-level extras.
- barbell_shrug (R4 §5.7): no spinal_loading flag although the barbell/trap-bar options hold deadlift-lockout-level loads through the arms (axial compression of the spine). If SL gates users with a logged back limitation, consider SL on this row with dumbbell_shrug as the offered substitution. Numbers unchanged.
- side_lying_dumbbell_external_rotation (R4 §5.7): increment 1.0 / 0.5 kg needs dumbbells below every preset's dumbbells.min_kg (2 kg) and 0.5-1 kg rack steps the presets do not model (step_kg 2). IncrementResolver cannot realise this increment in any default preset; progression will silently fall back to reps. Suggest 'reps; +1.0 kg where 1 kg steps exist' or a light-dumbbell requirement the resolver can check. Numbers unchanged.
- prone_y_raise (R4 §5.7): same increment problem (1.0 / 0.5 kg with a bodyweight default load type and a dumbbell option); progression should probably read 'reps; then +1.0 kg where available'. Numbers unchanged.
- Sources: NSCA Essentials chapter numbers cited (4th ed.: ch. 14 warm-up/flexibility, ch. 15 free-weight/machine technique, ch. 16 alternative modes) follow the SPEC §3.2 example and R4 S7 but R4 §7 item 2 states they are from memory; verify against the physical book before in-app display.
- Sources: only four ExRx pages relevant to this batch were fetched live per R4 §4.4 (Barbell Military Press, Lever Shoulder Press, Dumbbell Lateral Raise, Dumbbell Rear Lateral Raise). Other ExRx page names cited (Arnold Press, Push Press, Pike Push-up, Cable/Lever/Band Lateral Raise, Lever Rear Delt Fly, Cable Rear Delt Fly, Cable/Dumbbell Lying/Band External Rotation, Barbell/Dumbbell Shrug) are standard ExRx titles but were not fetched; R4 notes face-pull and rear-delt-machine URL guesses returned 404, so face_pull cites RP + R3 INJ-02/MOB-07 + Kolber 2010 instead. Integration pass should spot-check the unverified page names.
- band_external_rotation (R4 §5.7): equipment option is resistance_bands only while the row is unilateral; the anchored variant needs band_anchor_any. Content describes both an anchored and a hand-held (free hand fixed at the navel) variant so the row stays satisfiable as printed. Informational, no numbers changed.
- R4 §1 intro says the authoring batches are 'defined in §5.9'; they are in §5.12 (§5.9 is batch 4's table). Doc cross-reference typo, informational.

## batch_5.json (26 entries)
- FORMAT (task vs SPEC): the task asked for a top-level "review_notes": {id: text} map, but SPEC §2 ContentOverlay has only schema_version/batch/entries/status and SPEC HR-9/§3 decode knowledge assets with CoreJson.assets (ignoreUnknownKeys = false), so a top-level map would fail the strict loader. SPEC wins: review notes are written as the per-entry ExerciseContent.review_notes string (SPEC line ~1210, R4 §6.2 content.review_notes). Entries carrying one: good_morning, reverse_hyperextension, hip_adduction_machine, ankle_dorsiflexion_rock.
- FORMAT (R4 vs SPEC): R4 §5.12 says batch authors set content_status: "draft" per exercise; SPEC §3.2 puts status in the overlay's top-level status map. Followed SPEC (status map, all 26 = "draft").
- good_morning: equipment option is bb_loaded+rack_any (safeties high) while the SP flag and R4 §6.3 rule 6 require an option containing rack_or_spotter or a Smith machine; rack_any admits squat_rack, which R4 §2.3 says does not satisfy rack_or_spotter. Suggest bb_loaded+rack_or_spotter in exercises.json (WP-02) so Availability.safetiesOrSpotter matches the flag.
- reverse_hyperextension: carries no LB flag while back_extension_45 (its first-ranked substitute source) does; the pendulum can drive the lumbar spine into extension under momentum at the top. Either set LB or document that the fixed trunk is the reason it is the gentler option, since the choice affects users with a logged back limitation.
- hip_adduction_machine: substitutions sumo_deadlift (advanced; SL/LB/KN) and goblet_squat are compound swaps for a beginner isolation machine and cover the adductors only as secondary muscles; the planner should keep the R4 §5.3 difficulty gate and flags in force when swapping. The cable option inside the exercise is the closer like-for-like swap.
- ankle_dorsiflexion_rock: first substitute couch_stretch targets hip flexors/quads, not ankle dorsiflexion; R3 MOB-07 ankle row suggests a wall calf stretch or heel-elevated squat as the closer swap (single_leg_calf_raise is a fair second). R3 MOB-07 also names a 10 cm knee-to-wall threshold; if the app reports the test result that number belongs in exercises.json.
- SOURCES caveat (R4 §7 item 2): NSCA Essentials chapter numbers (ch. 14 warm-up/flexibility, ch. 15 free-weight/machine technique, ch. 16 alternative modes) are the 4th-edition numbers as used in the SPEC §3.2 example and must be checked against the physical book before in-app display; R4 notes the 5th edition renumbers them 16/17.
- SOURCES caveat: ExRx page names for Trap Bar Deadlift, Barbell Sumo Deadlift, Barbell Good-morning, Dumbbell Straight-leg Deadlift, Cable Pull Through and Kettlebell Swing were not among the pages R4 §4.4 fetched live; they are standard ExRx page titles but unverified in R4. Machine hip thrust, glute bridge and reverse hyper cite the verified family page (Barbell Hip Thrust / Weighted Hyperextension) with a variant note. Peer-reviewed sources cited by author/year per R4 §5.13 rule 1: van Dyk 2019 (Nordic), Serner 2014 + Haroy 2019 (Copenhagen), Cambridge 2012 (band walk), Bennell 1998 (knee-to-wall), Behm 2016 (dynamic warm-up).

## batch_6.json (28 entries)
- hanging_leg_raise: lying_leg_raise carries low_back_sensitive but hanging_leg_raise does not; the straight-leg hanging version has the same anterior-tilt mechanism (R4 §5.5 'leg raises with anterior tilt') on a longer lever. Suggest LB on this row too, or a table note that the knee-raise version is the LB-free regression. Numbers/flags not changed.
- treadmill: the table's 'KN (running)' is conditional but flags.knee_sensitive is a boolean. If WP-02 sets it true, knee-limited users lose incline walking, which R3 CAR-08 and INJ-01 name as the knee-friendly, leg-day-adjacent option. Suggest split ids treadmill_walk (KN false) / treadmill_run (KN true), or knee_sensitive false with the running caveat in content.
- outdoor_run_walk: same boolean-vs-conditional problem as treadmill; a true flag hides brisk walking (R3 INJ-03 / STP-01 daily baseline) from knee-limited users. Suggest outdoor_walk / outdoor_run split or knee_sensitive false with the caveat in content.
- R4 §5.2 core_time profile: the notes column says 'not beyond ~60 s' while the endurance column says 30–90 s; internal R4 tension, so the plank/side-plank content says 'progress by lever or load rather than longer holds' without quoting a seconds figure.

## batch_1.json (26 entries)
- close_grip_bench_press: the second equipment option (smith_machine+bench_flat_any, load type smith) inherits the exercise-level requires_spotter_or_safeties flag, yet a guided bar hooks onto its rails at any height and smith_bench_press carries no SP flag. As written, a Smith-only gym gets the RIR-2 cap and the safeties note although the mechanism is already covered. Suggest a note on that option or letting the resolver treat a smith option as satisfying rack_or_spotter.
- low_to_high_cable_fly: R4 §5.6 gives cable_fly an increment of 2.5 / 2.5 marked '(per side)' but low_to_high_cable_fly the same 2.5 / 2.5 without the note, although both use two stacks (cable_dual_any). If '(per side)' becomes per_hand: true in exercises.json, the two rows should agree.
- lying_triceps_extension: no requires_spotter_or_safeties flag although the bar travels over the face. The escape is a close-grip press rather than a trapped bar, so the flag is defensible, but the planner should not pick the barbell/EZ option for AMRAP or failure sets (RIR-05 calibration); the dumbbell option or a cable exercise is the safe choice. R4 §4.4 also lists the ExRx lying-extension page as unverified, so the sources cite the family page (Cable Pushdown).
